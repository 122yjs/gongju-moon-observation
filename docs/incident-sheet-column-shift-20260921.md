# 관찰 기록 열 밀림 조사와 복구 — 2026-09-21

## 원본에서 확인한 문제

학생 사진은 Drive에 있지만 앱에서 기록이 보이지 않는 제보를 조사했다. 연결된 267개 학급을 대상으로 원본 시트의 **전체 열**과 사진 폴더를 대조했다. 앱이 조회하는 A:S 범위만 확인하면 오른쪽으로 밀린 기록을 실제 미저장으로 오판할 수 있다.

원본에서 관찰 ID·요청 ID부터 시작하는 완전한 기록이 Q열 또는 S열부터 연속해서 저장된 것을 확인했다. 기존 목록과 단건 조회는 A열의 관찰 ID를 기준으로 하므로 이 기록들을 읽지 못했다. 메모·사진 파일 ID·관찰 시각·제출 시각·피드백·공개 상태는 오른쪽 열에 남아 있었다.

오래된 `append/active` 잠금 두 건도 해당 관찰 ID를 오른쪽 열에서 찾았다. 정상 열 순서로 해석한 내용 버전이 잠금에 기록된 `intended_version`과 일치했다. 기존 점검은 A열에서만 관찰 ID를 찾으므로 저장 완료를 확인하지 못한 상태였다.

## 재발 방지 변경

Google Sheets `values.append`의 range는 입력값의 열 수를 제한하는 것이 아니라 **기존 표를 찾을 범위**를 정한다. A:S 전체를 탐색하면 오른쪽 선택 항목을 기준으로 한 별도 표로 기록이 이어질 수 있었다.

- 새 기록의 표 탐색 범위를 A:A로 고정한다. 입력값은 기존과 동일하게 19개 열을 전달한다.
- Google 응답의 `updatedRange`가 A열부터 S열까지 한 행인지 확인한다.
- 다른 위치, 여러 행 또는 확인할 수 없는 응답이면 성공 처리하지 않는다. 이미 올라간 사진과 저장 잠금을 보존해 운영자 확인이 가능하게 한다.

저장 경로와 응답 위치 검증 회귀 테스트 두 건은 변경 전 실패했고 변경 후 통과했다. 앱 전체 테스트 210개, 빌드, 변경 파일 ESLint와 `git diff --check`를 통과했다.

## 복구 방법

1. 개인정보가 포함된 원본은 Git 추적에서 제외되는 `outputs/recovery-20260921/`에 저장했다. 디렉터리는 소유자 전용, JSON 백업 파일은 읽기·쓰기 권한을 소유자로 제한했다. 키·토큰은 보고서와 소스에 저장하지 않는다.
2. 각 학급의 전체 원본을 실행 직전에 다시 읽고 별도 백업했다. 백업의 내용 해시와 현재 내용이 같은 경우에만 진행한다.
3. 정상 데이터가 앞에 없는 행, 알려진 기록 구조, 중복되지 않는 관찰 ID만 이동 대상으로 삼는다. 알 수 없는 추가 내용이 있으면 해당 학급의 쓰기를 거부한다.
4. 시트별 잠금으로 앱의 동시 쓰기를 막고 다시 원본을 대조한다. 기존 잠금은 같은 학급·관찰 ID·내용 버전이 확인된 경우에만 소유권을 조건부로 넘겨받는다.
5. 한 번의 `values:batchUpdate`로 해당 행의 기록을 A:S로 옮기고 오른쪽에 남은 내용을 정리한다. 정상 행, 행 번호, 사진 파일, 비공개 상태와 원문은 유지한다.
6. 전체 시트를 다시 읽어 예상 결과와 같은지 확인한 뒤 해당 관찰의 행 색인과 제출 영수증을 복구하고 잠금을 해제한다. 별도 클라이언트가 다시 읽어 이동한 각 행을 원본과 대조한다.
7. 쓰기 결과가 불분명하면 잠금을 유지하고 후속 처리를 중단한다. 같은 도구를 정상화된 원본에 재실행해도 새 기록을 추가하지 않는다.

복구 도구는 인증과 만료 시각을 가진 임시 Worker 버전으로 실행하며 운영 트래픽에는 배포하지 않는다. 운영 앱에는 재발 방지 수정만 적용한다. 커밋·푸시는 별도 사용자 요청 없이는 수행하지 않는다.

- 기존 시트 잠금 2건을 해제했고 종료 시 잔여 시트 잠금은 0건이다. 원래 요청 내용이 확인되지 않는 재시도 제출 영수증 1건은 임의로 완료 처리하지 않았다.
